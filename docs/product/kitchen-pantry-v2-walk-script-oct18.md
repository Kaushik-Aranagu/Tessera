# Pantry v2 acceptance walk script

For: whoever runs the walk the moment Core's Pantry v2 PR lands. Written Sun Oct 18. Static read only: no Swift toolchain here, nothing is built or run, so a PASS below means "I read the code and the test and they match the fixture", never "the test ran green". Running `swift test` and `scripts/test.sh` stays a Mac step (see Still open).

Inputs: `docs/research/fixtures/pantry-v2.md` (Research #902, revision 2), `docs/product/kitchen-gap-hunt-12-pantry-v2-spec-oct17.md` (the spec, clauses S/E/V/U/M/C/F/P, R1 to R20 ruled with every recommended default accepted), `docs/product/pantry-acceptance.md`, and the Pantry files on origin/master (`Features/Kitchen/Pantry*.swift`, `TesseraTests/Pantry*.swift`). Rows below copy the fixture's expected text; where I name a Swift symbol that does not exist on master yet, it is marked inferred.

**Counts.** 175 rows in your seven groups: PD 32, PB 20, PG 53, PW 20, PP 17, PO 8, PR 25. The fixture also has 24 PE (edge case) rows, an eighth prefix you did not list; they sit in an appendix so nothing is dropped (gap G177). Ids the fixture skips on purpose or by accident: PG28, PG29, PG38, PG39.

**Rulings this walk grades against** (from the fixture, section 0, as Product's 4:32 pm Oct 17 rulings): (1) tie rule, one rule for backfill and live writes: at an equal timestamp the surer state wins (out over low over in), and an older timestamp never overwrites a newer one; (2) the backfill marker is the Settings key `pantryBackfilled`, set when the backfill finishes, never inferred from "any ingredient has state"; (3) `Egg` and `Eggs` fold to one key through `IngredientLine.key(for:)` (Quantities.swift:283 on 0d81f1a3), latest timestamp wins, ties by rule 1; (4) 118 distinct test names; (5) `PantryLedgerTests`, `PantryFrontTests` and `GroceriesFinishTests.undoAfterFinishPutsPantryBack` are rewritten for stored state, with no catalog number hard-coded. R12 follows G102: a private Pantry line reads "Private item" and has no reveal and no tap target. Heads up: the decisions entries these come from are not on origin/master (G170).

## Before you start

1. Fetch and read the base. The fixture was written against `0d81f1a3`; origin/master was `6899613b` when I wrote this, so line numbers quoted from the fixture may have drifted (re-find by the grep, not the number). Never switch branches or check anything out; read everything with `git show` and `git grep` on a SHA.

```bash
cd /home/user/Tessera
git fetch origin --prune
git log -1 --format='%H %s' origin/master
```

2. Find Core's PR. It is not known yet (inferred: it touches `SystemCatalog.swift`, `TessGrammar+Kitchen.swift`, `Shopping.swift`, `Cooking.swift`, `Groceries.swift` and adds Pantry tests).

```bash
gh pr list --state all --limit 30 --search "pantry in:title,body" \
  --json number,title,state,mergedAt,mergeCommit,headRefName,author
# fallback by files touched:
gh pr list --state merged --limit 30 --json number,title,mergeCommit,files \
  --jq '.[] | select(any(.files[]; .path|test("SystemCatalog|TessGrammar\\+Kitchen"))) | [.number,.title,.mergeCommit.oid]|@tsv'
```

3. Map the merge SHA, then confirm it is on master and which files it changed. If the PR is still open, use its head SHA and mark every verdict "pre-merge" in your notes.

```bash
PR=<number>                                   # fill in
R=$(gh pr view $PR --json mergeCommit --jq .mergeCommit.oid)   # squash or merge commit
git fetch origin && git merge-base --is-ancestor $R origin/master && echo "in master"
git show --stat --format='%H %s' $R | head -60
gh pr view $PR --json files --jq '.files[].path' | sort > /tmp/pr-files.txt   # scratch only
# helper used by every row: grep a SHA without checking it out
g() { git grep -nE "${1//~/|}" "$R" -- "${@:2}"; }   # ~ in a pattern means alternation (a pipe breaks the table)
C=TesseraCore/Sources/TesseraCore; K=$C/Kitchen; F=Features/Kitchen
T=TesseraCore/Sources/TesseraTess/TessGrammar+Kitchen.swift
```

4. Test-name sweep. Every row names the test that should cover it. This lists names from this file that no test file defines at `$R`; each missing name is "test NOT BUILT" for its row.

```bash
WALK=/tmp/claude-0/-home-user/504a25e2-29ee-50a7-8fec-5eab60c7a5a8/scratchpad/pantry-v2-walk-script.md
awk -F'|' '/^\| P[DBGWPOR][0-9]+ /{print $6}' "$WALK" | grep -oE '`[a-z][A-Za-z0-9]+`' | tr -d '`' | sort -u |
while read n; do
  git grep -qE "func $n\b" "$R" -- TesseraCore/Tests TesseraTests || echo "NO TEST: $n"
done
```

5. Verdict words. PASS: the code at `$R` does what the Expected cell says and a test that asserts it exists (read, not run). FAIL: the code contradicts Expected, or the test asserts something else. NOT BUILT: the grep and a wider search find no symbol for it. NOT PROVABLE: needs the phone or a run, or an input nobody has ruled (see Phone only and Still open). Fill the last column of each row with one of those four words and a file:line.
6. Hygiene. Do not paste, print or store any Claude key anywhere in notes. PG50 uses a key-shaped tail that the test builds at run time; check the test builds it, do not type one in. If the PR changed a user-facing string, check US English, lowercase clocks with no "at" before a time, and thing-first receipts with "on" while you are there.
7. Scope check before grading. Run `cat /tmp/pr-files.txt`. Rows owned by Builder B (PW, PP02, PP05, PO) need the Builder B PR too, not Core's; if it is separate, repeat steps 2 and 3 for it and note both SHAs in the table header you fill in.

Legend for the "What to read" column (a `~` inside a grep pattern means alternation, because a pipe would break the table; the `g` helper turns it back): `$C` core sources, `$K` core Kitchen folder, `$F` app Features/Kitchen, `$T` the Tess grammar file, `g` the helper above. "(inferred)" means the name comes from the spec, not from code. The Clause column also shows the owner. In the Test column the square brackets give the test file (from the spec's section (e) list, or inferred for Builder B rows, whose tests would sit in `TesseraTests`).
