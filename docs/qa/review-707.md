SQLite DELETE leaves the old row bytes in free pages of the file unless secure_delete is on or the file is VACUUMed, and nothing in the diff sets either (no VACUUM or secure_delete anywhere in TesseraCore). The new tests only re-open the copy and re-export it, so they prove the rows are gone logically, not that the words are gone from the file. A strings dump of the folder copy may still show a private note, recipe or "Pay Dr Lee".

Also build and mask the copy in a temp directory and move it into the iCloud folder, so the unmasked full copy never exists under the synced folder even as a hidden .partial.
