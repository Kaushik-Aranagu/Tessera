# Review #710 (head be03cd9d): FIX FIRST (one point), static
Stacked on #707's 1a3d64e0; I reviewed only the delta.
## Blocking: the narrower title rule misses a bare medicine
PrivateWords.isPrivateTitle is now isPrivateText (SecretWords.mentions or PrivateFacts.isWalled) or a word in titleWords (money words, TessMemoryScreen.healthWords, a few care words). A medicine name counts as a body fact in PrivateFacts only next to a number or "mg" ("advil 200"); a bare "Lexapro", "advil" or "take melatonin" is not isWalled. The medicine list (PrivateFacts.medicines) lives in EngineWall.isHealth, which the new rule does not call. Lists.swift says it outright: a kept list item that is a medicine "shows on his list, nothing else names it", and the capture, receipt and summary all say "Private item". So the item (and the Groceries row and ingredient object for "advil") keeps its real title, and the shared export and the iCloud copy now carry it. (The old Home-wall rule did not catch it either, so this predates #710, but Product's ruling is that a medicine name is a health fact everywhere, and the tests do not include one.) Tasks and recipes are fine: tasks become "Private task" at capture, and recipes use isPrivateRecipeTitle, which includes isHealth.
Fix: add `|| EngineWall.isHealth(title, lastWeightKg:)` to isPrivateTitle (it then also feeds wordyTitle and the history scan), and add a test with a "lexapro" list item, an "advil" groceries row and "take melatonin" that fails if any of them appears in the export JSON or the raw bytes of the iCloud copy.
## Checked and fine
- Face ID: the only app path to a saved copy is BackupView.saveCopy, which calls BackupKeeper.savedCopy; the gate asks for .deviceOwnerAuthentication whenever requiresAuth (always true), a cancel or failure returns nil and nothing is made or said; the `authenticate` seam is a test hook. The copy stays whole, and "This copy has your private words." shows only when labels or past labels exist. (copyForSaving is still callable without auth; keep it internal.)
- Fold: a "Groceries" list folds only when its create op came from an action other than createList and it has no createList create op; a list with no create op at all is left alone, a renamed or Tess-made list has the createList op, so one he named never merges. The receipt goes through the launch note and never over an existing one. The stray's rows move and it is soft-deleted as before.
- Key tests build the prefix from parts; privateWorkURL is temporaryDirectory/UUID/private.tessera with a defer that removes the folder even when a step throws, and the final file is the only thing moved in. False positives: number lists skip the money rule, "Day 100" no longer hits the 3-digit rule, "Call mom" is no longer masked (Product's call). Caches are per revision and the summary line check is memoized.
## Lows
- The decoded-ops cache keeps every OpRecord's decoded ops in memory for the life of the context; at 5-year size that is a lot of strings held forever. Clear it after the backup or cap it.
- historyLabels skips number-list titles, so an old op that renamed an object to a bare "120.50" is not treated as private history.
- Face ID: .deviceOwnerAuthentication throws when no passcode is set, so SAVE A COPY would never run on a passcode-less phone; say so in the line or allow it.
