# Tessera

> **Standing principle (Kaushik):** UI carries equal weight with the backend (50/50). UI is a place for real
> invention, creativity and new solutions, not polish on top. Never ship stock or card-based screens.

The repo folder is `~/pilot` (the app was renamed from Pilot to Tessera; the folder name stays). The in-app
personal assistant is called **Tess**.

Personal iPhone-only app, native SwiftUI. **Read `docs/PRODUCT_VISION.md` first**: everything is a linkable,
class-based object (OOP/OS concepts), with dense information revealed progressively. Training (workout logging,
plans, PRs, live workout mode) is the first domain.

## Platform & stack
- iPhone only (no iPad, Mac or watch targets). Deployment target: iOS 27.0+ — use iOS 27 APIs freely; no `#available` fallbacks for older OSes.
- UI: SwiftUI. Use modern APIs (Observation `@Observable`, Swift concurrency, Swift 6 strict concurrency).
- Persistence: SQLite through GRDB (chosen after `docs/research/storage-spike.md`), behind the TesseraCore engine: the whole object graph lives in memory (`TesseraContext`) and writes through to `Application Support/Tessera/tessera.sqlite`. The app never touches the database directly; use `ObjectStore`. iCloud sync (CKSyncEngine over the op log) is parked until there is a second device.
- System integrations: WidgetKit (widgets), ActivityKit (Live Activities), HealthKit, App Intents (Shortcuts/Siri/Spotlight).
- On-device AI: Apple Foundation Models framework. No third-party/cloud LLM calls unless explicitly decided.

## Project
- Generated by XcodeGen from `project.yml`. `Tessera.xcodeproj` is gitignored; run `xcodegen generate` after cloning or after adding/removing files or changing targets/settings. Never hand-edit the .xcodeproj.
- Targets: `Tessera` (app, bundle id `com.kaushikaranagu.tessera`), `TesseraTests` (Swift Testing). Scheme: `Tessera`.
- Layout: `App/` (entry point, root view), `DesignSystem/` (`Theme` tokens: colors, type, spacing, radius, motion — use these instead of literals), `TesseraCore/` (local Swift package, module `TesseraCore`, the engine; no UI): `Model/` (models `ClassDef`, `FieldDef`, `ObjectRecord`, `ObjectLink`, `ViewDef`, `OpRecord`; `TesseraContext` + GRDB schema; `TesseraSchema.makeContainer`), `Engine/` (`ClassResolver`, `ObjectStore`, `Formula`, `ObjectPath` — read/write objects through these, never raw `valuesData`), `Catalog/` (`SystemCatalog` built-in classes, seeded at launch), `Training/` (`TrainingLedger`: history, PRs, trends, e1RM, weekly sets). Run its tests on the Mac with `swift test` inside `TesseraCore/`. `Features/<Feature>/` (one folder per screen/feature), `TesseraTests/`.
- Data model: see the table in `docs/PRODUCT_VISION.md`. `TesseraLegacyStore` moves data from the old SwiftData store into GRDB once at launch. No entitlements yet (no paid developer account).
- Dev simulator: iPhone 17 (iOS 27 runtime). MobileBuildMCP defaults are saved in `.mobilebuildmcp/config.yaml`.

## Build & test
Prefer the MobileBuildMCP tools (`build_run_sim`, `test_sim`, `screenshot`). Shell fallback, piped through `xcbeautify`:

```bash
xcodegen generate
xcodebuild -scheme Tessera -destination 'platform=iOS Simulator,name=iPhone 17' build | xcbeautify
xcodebuild -scheme Tessera -destination 'platform=iOS Simulator,name=iPhone 17' test | xcbeautify
```

## Before opening a PR
There is no CI. Run `scripts/test.sh` (engine package tests, then the app build and tests on the simulator;
`--package-only`, `--app-only`, `--scale` for the 5-year history test) and only open the PR when it ends "All green".

## Before committing
```bash
swiftformat .
swiftlint
```
Fix lint errors before committing. Don't commit build products, DerivedData or `xcuserdata`.

## Design & motion
Use the `tessera-design` skill (`.claude/skills/tessera-design`) — all visuals go through the swappable `ThemeConcept` — and read `docs/DESIGN_MOTION.md` before building or changing any UI. Animate only through `MotionPolicy` (`.tesseraAnimation`, `withTesseraAnimation`). The bar is first-party-Apple polish, not a generic
app: continuous transitions, spring physics, haptics, Liquid Glass on the navigation layer only, Reduce Motion /
Dynamic Type respected. Use the installed skills (Apple's `swiftui-specialist` / `swiftui-whats-new-27` / accessibility specialists,
`swiftui-pro`, `swiftui-expert`, `swiftui-ui-patterns`, `liquid-glass`, `widgets`, `swiftdata-pro`, framework skills)
and verify APIs with the `xcode` MCP `DocumentationSearch` or the `sosumi` MCP rather than guessing.

## Tooling notes
- MCP servers (`.mcp.json`): `MobileBuildMCP` (build/run/test, UI automation, video, debugging; config in
  `.mobilebuildmcp/config.yaml`), `xcode` (Apple's `xcrun mcpbridge`: DocumentationSearch, RenderPreview, device
  interaction — Xcode must be running with this project open), `sosumi` (Apple docs, HIG, WWDC transcripts).
- Apple's Xcode agent skills are copied into `.claude/skills/` but gitignored. After an Xcode update, refresh them from
  `$(xcrun agent plugin path --plugin-format claude)/skills/`.

## Running the demo
- `-demoTime HH:mm` (DEBUG) shifts the app clock so the demo day looks the same at any hour; `-demo` seeds the demo history (off by default, so it never lands on the phone); `-resetDemo` wipes and
  reseeds demo data; `-theme <name>` picks a theme concept. Example: `-demoTime 18:10 -resetDemo`.
- Raw simulator recordings (`docs/recordings/raw-*.mp4`) are gitignored; trimmed clips are kept.
